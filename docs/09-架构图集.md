## 3. 查询循环流程图

展示 query.ts 中核心查询循环的完整流程。每次迭代从技能发现预取开始，经过消息获取、工具结果预算、snip 压缩、微压缩等步骤后调用 Claude API。若响应包含工具调用则执行工具并检查是否需要自动压缩，然后根据 token 预算和最大轮次决定是否继续迭代。

```mermaid
flowchart TD
    Start([开始迭代]) --> A[技能发现预取]
    A --> B[查询链追踪初始化]
    B --> C[获取compact boundary后的消息]
    C --> D[应用工具结果预算]
    D --> E[应用snip压缩]
    E --> F[应用微压缩]
    F --> G[调用Claude API]
    G --> H{响应包含工具调用?}
    H -->|否| I[结束循环]
    H -->|是| J[执行工具 runTools]
    J --> K[处理stop hooks]
    K --> L{需要自动压缩?}
    L -->|是| M[执行自动压缩]
    M --> N{max_output_tokens恢复?}
    L -->|否| N
    N -->|是| O[恢复max_output_tokens]
    N -->|否| P{token预算检查}
    O --> P
    P -->|超预算| I
    P -->|未超| Q{达到max_turns?}
    Q -->|是| I
    Q -->|否| Start

    style Start fill:#e1f5fe
    style I fill:#ffcdd2
    style G fill:#c8e6c9
    style J fill:#fff9c4
```

## 4. 工具生命周期时序图

展示工具从定义到执行的完整生命周期。QueryEngine 发起工具调用后，runTools 负责查找工具、验证输入、检查权限。若需要用户确认则弹出对话框。权限通过后渲染工具使用消息，调用工具实现，支持进度报告回调，最终返回工具结果并渲染到 UI。

```mermaid
sequenceDiagram
    participant QE as QueryEngine
    participant RT as runTools
    participant PM as 权限管理
    participant User as 用户
    participant Tool as 工具实现
    participant UI as UI渲染

    QE->>RT: 执行工具调用
    RT->>RT: findToolByName()
    RT->>Tool: validateInput(input)
    Tool-->>RT: 验证结果

    RT->>PM: checkPermissions(input, context)
    PM-->>RT: PermissionDecision

    alt 需要用户确认
        RT->>UI: 显示确认对话框
        UI->>User: 请求确认
        User->>UI: 允许/拒绝
        UI-->>RT: 用户决策
    end

    alt 权限允许
        RT->>UI: renderToolUseMessage()
        RT->>Tool: call(input, context)

        loop 进度报告
            Tool-->>RT: onProgress(progress)
            RT->>UI: renderToolUseProgressMessage()
        end

        Tool-->>RT: ToolResult
        RT->>UI: renderToolResultMessage()
        RT-->>QE: 工具结果消息
    else 权限拒绝
        RT-->>QE: 权限拒绝消息
    end
```

## 5. 上下文压缩策略图

展示三层压缩策略的工作流程。微压缩（MicroCompact）在每次 API 请求前执行，包含缓存编辑清理和时间阈值清理。自动压缩（AutoCompact）在 token 超过阈值时触发，优先尝试 sessionMemoryCompact，失败则进入完整压缩流程：Fork Agent 生成结构化摘要（9个部分），清理缓存状态，重新注入附件。

```mermaid
flowchart TD
    subgraph "每次API请求前"
        MC[微压缩 MicroCompact]
        MC --> CMC[Cached MicroCompact<br/>cache_edits API]
        MC --> TBMC[Time-Based MicroCompact<br/>时间阈值清理]
    end

    subgraph "Token超过阈值"
        AC[自动压缩 AutoCompact]
        AC --> SMC{sessionMemoryCompact<br/>成功?}
        SMC -->|是| Done[压缩完成]
        SMC -->|否| FC[完整压缩 Full Compact]
        FC --> FA[Fork Agent]
        FA --> Sum[生成结构化摘要<br/>9个部分]
        Sum --> Cleanup[清理缓存状态]
        Cleanup --> Reinject[重新注入附件]
        Reinject --> Done
    end

    subgraph "摘要结构"
        Summary["summary"]
        Summary --> S1[主要请求]
        Summary --> S2[技术概念]
        Summary --> S3[文件/代码]
        Summary --> S4[错误修复]
        Summary --> S5[问题解决]
        Summary --> S6[所有用户消息]
        Summary --> S7[待办任务]
        Summary --> S8[当前工作]
        Summary --> S9[下一步]
    end

    style MC fill:#e3f2fd
```

## 6. 消息处理管线图

展示消息从 API 响应到终端渲染的处理管线。消息经过标准化、UI 排序、分组后，依次折叠背景 Bash 通知、Hook 摘要、Teammate 关闭、Read/Search 分组等次要消息。若消息数超过 200 条则启用虚拟滚动，最终由 Message.tsx 根据消息类型路由到对应的渲染组件。

```mermaid
    VScroll -->|是| Virtual[VirtualMessageList<br/>虚拟滚动]
```

## 7. 权限系统流程图

展示三层权限架构的决策流程。工具调用请求首先经过 Deny 规则匹配（黑名单），再经过 Allow 规则匹配（白名单）。若均未命中，则检查工具是否为只读操作。只读工具自动允许，其他工具弹出确认对话框。用户可选择"始终允许"（保存规则）、"允许一次"或"拒绝"。

```mermaid
flowchart TD
    Input[工具调用请求] --> Parse[preparePermissionMatcher<br/>解析命令/路径]
    Parse --> Deny{Deny规则匹配?}
    Deny -->|是| Reject[拒绝执行]
    Deny -->|否| Allow{Allow规则匹配?}
    Allow -->|是| Auto[自动允许执行]
    Allow -->|否| Check{工具属性检查}
    Check --> ReadOnly{isReadOnly?}
    ReadOnly -->|是| Auto
    Check -->|否| Ask[显示确认对话框]
    Ask --> User{用户决策}
    User -->|Always Allow| SaveRule[保存Allow规则]
    User -->|Allow Once| Execute[执行一次]
    User -->|Deny| Reject
    SaveRule --> Execute

    style Reject fill:#ef9a9a
    style Auto fill:#a5d6a7
    style Ask fill:#fff59d
```

## 12. 构建系统架构图

展示 Bun 构建系统的架构。入口为 `src/entrypoints/cli.tsx`，通过 Bun Bundler 打包。构建过程中使用 Feature Flag Plugin（90+ flags）进行条件编译和 Dead Code Elimination，Text File Loader 处理 `.md`/`.txt`/`.d.ts` 等文本文件的字符串导入。原生模块（`.node`）、sharp 和 Anthropic SDK 作为外部依赖不打包。最终产出约 21MB 的 `dist/cli.js`，添加 shebang 并设置 0o755 权限。

```mermaid
flowchart TD
    Entry["src/entrypoints/cli.tsx"] --> BunBuild["Bun Bundler"]

    subgraph "Bun 插件"
        Plugin1["Feature Flag Plugin<br/>90+ flags"]
        Plugin2["Text File Loader<br/>.md/.txt/.d.ts"]
    end

    BunBuild --> Plugin1
    BunBuild --> Plugin2

    Plugin1 -->|替换为常量| DCE["Dead Code Elimination"]
    Plugin2 -->|字符串导入| Bundle["Bundle"]

    subgraph "External"
        Ext1["*.node 原生模块"]
        Ext2["sharp"]
        Ext3["@anthropic-ai/* SDK"]
    end

    Bundle --> Ext1
    Bundle --> Ext2
    Bundle --> Ext3

    Bundle --> Dist["dist/cli.js<br/>~21MB"]
    Dist --> Shebang["添加 shebang<br/>#!/usr/bin/env node"]
    Shebang --> Perm["设置权限<br/>0o755"]
    Perm --> Output["最终产出"]
```
