# Claude Code 源码深度分析 - 00 项目概览

## 1. 项目背景

本文档是对 Claude Code 仓库的完整项目概览分析。Claude Code 是 Anthropic 官方推出的 AI 编程助手命令行工具，以交互式终端应用的形式提供代码生成、编辑、搜索、调试等能力。

### 1.1 项目基本信息

| 属性 | 值 |
|------|-----|
| **包名** | `cloud-code-source` |
| **版本** | `2.1.88` |
| **模块类型** | ESM (`"type": "module"`) |
| **私有包** | 是 (`"private": true`) |
| **可执行入口** | `./dist/cli.js` (bin: `claude`) |
| **源文件总数** | ~1,908 个 TypeScript/TSX 文件 |
| **源码目录数** | 34 个子目录 + 根目录 20 个散落文件 |
| **核心依赖** | 94 个 |
| **开发依赖** | 5 个 |
| **特性开关** | 90 个 |

### 1.2 来源说明

本项目是从 `@anthropic-ai/claude-code` npm 包 v2.1.88 的 `cli.js.map` source map 中还原出的完整 TypeScript 源码。源码经过还原后保持了原始的目录结构和模块组织方式，可以正常构建和运行。

## 5. 构建系统

### 5.1 构建配置 (build.ts)

Claude Code 使用 Bun 的内置 bundler 进行构建，构建脚本位于项目根目录的 `build.ts`。

#### 核心构建参数

```typescript
const result = await Bun.build({
  entrypoints: ['./src/entrypoints/cli.tsx'],  // 单一入口
  outdir: './dist',                              // 输出目录
  target: 'node',                                // 目标平台
  format: 'esm',                                 // ESM 格式
  sourcemap: 'linked',                           // 关联 source map
  minify: false,                                 // 不压缩（便于调试）
})
```

#### 编译期常量替换 (MACRO)

构建时通过 `define` 注入版本信息和环境常量：

```typescript
define: {
  'MACRO.VERSION': JSON.stringify('2.1.88'),
  'MACRO.BUILD_TIME': JSON.stringify(new Date().toISOString()),
```

#### Bun 插件系统

构建过程使用两个自定义 Bun 插件：

**1. 特性开关插件 (`bun-bundle-feature-shim`)**

拦截 `bun:bundle` 虚拟模块导入，将 `feature()` 调用替换为编译期常量值。这使得未启用的特性分支会在构建时被 dead code elimination 移除，减小产物体积。

```typescript
// 源码中的写法
import { feature } from 'bun:bundle'
if (feature('VOICE_MODE')) {
  // 语音模式代码
}
```

构建后等价于：

```javascript
// 构建后
if (false) {
  // 语音模式代码 -- 会被压缩工具移除
}
```

**2. 文本文件加载器 (`text-file-loader`)**

- `.md` / `.txt` 文件作为字符串常量导入
- `.d.ts` 文件作为空模块处理（仅类型声明）

#### 构建后处理

构建成功后自动执行以下操作：

1. 在输出文件头部添加 shebang：`#!/usr/bin/env node`
2. 设置文件权限为 `0o755`（可执行）
3. 输出构建结果和文件大小

## 7. 特性开关系统

### 7.1 机制概述

Claude Code 实现了一套编译期特性开关系统，通过 Bun bundler 插件在构建时将特性标志替换为布尔常量。这套机制的核心原理如下：

1. **声明**: 在 `build.ts` 中定义所有特性标志及其默认值
2. **引用**: 源码中通过 `import { feature } from 'bun:bundle'` 引入
3. **使用**: 通过 `feature('FLAG_NAME')` 检查特性是否启用
4. **替换**: Bun 插件在构建时将 `feature()` 调用替换为字面量 `true`/`false`
5. **消除**: 未启用的代码分支在 tree-shaking 阶段被自动移除

```typescript
// 源码示例
import { feature } from 'bun:bundle'

if (feature('VOICE_MODE')) {
  // 这段代码在当前构建中会被完全移除
  enableVoiceInput()
}
```

## 8. 架构概要

### 8.1 分层架构

Claude Code 的代码组织遵循清晰的分层架构：

```
┌─────────────────────────────────────────────┐
│              入口层 (entrypoints/)           │  CLI 启动、SDK 导出
├─────────────────────────────────────────────┤
│              UI 层 (components/ + ink/)      │  终端渲染、用户交互
├─────────────────────────────────────────────┤
│            业务逻辑层                        │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │commands/ │ │ tools/   │ │  services/   │ │
│  │斜杠命令  │ │工具实现  │ │  核心服务    │ │
│  └──────────┘ └──────────┘ └──────────────┘ │
├─────────────────────────────────────────────┤
│            基础设施层 (utils/)               │  工具函数、API、认证等
├─────────────────────────────────────────────┤
│            跨切面关注点                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ hooks/   │ │ state/   │ │  bridge/     │ │
│  │React钩子 │ │状态管理  │ │  IDE桥接     │ │
│  └──────────┘ └──────────┘ └──────────────┘ │
└─────────────────────────────────────────────┘
```

### 8.2 核心模块关系

- **QueryEngine** (`src/QueryEngine.ts`): 查询引擎，负责处理用户输入并调用 AI API
- **Task** (`src/Task.ts`): 任务执行器，管理单个任务的完整生命周期
- **Tool** (`src/Tool.ts`): 工具注册表，定义和管理所有可用工具
- **AppState** (`src/state/AppState.tsx`): 全局应用状态，基于 React Context
- **Ink** (`src/ink/`): 自研终端渲染引擎，替代原始 Ink 实现
- **Bridge** (`src/bridge/`): IDE 集成桥接层，支持 VS Code 和 JetBrains

### 8.3 数据流

```
用户输入 → CLI 解析 (commander) → REPL 启动
    → QueryEngine 接收查询
    → 构建 System Prompt (systemPrompt.ts + constants/)
    → 调用 Anthropic API (@anthropic-ai/sdk)
    → 接收 AI 响应（可能包含工具调用）
    → 执行工具 (Tool.ts → utils/ 中的具体实现)
    → 渲染结果 (components/ → ink/ 渲染引擎)
    → 更新状态 (state/ → hooks/ 通知组件更新)
```

## 9. 关键设计决策

### 9.1 自研终端渲染引擎

Claude Code 没有直接使用 Ink 的原始实现，而是在 `src/ink/` 中自研了一套基于 `react-reconciler` 的终端渲染引擎。这使得项目能够：

- 精确控制终端渲染性能
- 实现自定义的文本测量和布局
- 支持双向文本（bidi）
- 实现终端焦点管理和选择功能
- 支持超链接和搜索高亮

### 9.2 编译期特性开关

通过 Bun bundler 插件实现的编译期特性开关系统，相比运行时特性开关具有以下优势：

- **零运行时开销**: 特性检查被替换为字面量，无函数调用
- **完美 tree-shaking**: 未启用的代码分支被完全移除
- **类型安全**: `feature()` 函数返回布尔值，TypeScript 类型检查正常工作
- **构建可重现**: 特性标志在构建时确定，产物行为一致

### 9.3 多云支持

通过统一的抽象层支持多个 AI 服务提供商：

- **Anthropic API**: 直接调用
- **AWS Bedrock**: 通过 `@aws-sdk/client-bedrock`
- **Google Vertex AI**: 通过 `@anthropic-ai/vertex-sdk`
- **Azure**: 通过 `@azure/identity`

### 9.4 完整的可观测性

集成 OpenTelemetry 实现了完整的可观测性方案：

- **Traces**: 分布式追踪，覆盖 API 调用、工具执行等关键路径
- **Metrics**: 性能指标，包括延迟、吞吐量、Token 使用量等
- **Logs**: 结构化日志，支持 OTLP 导出（gRPC/HTTP/Proto）
- **Prometheus**: 支持 Prometheus 指标导出
