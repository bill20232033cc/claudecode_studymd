# Claude Code 源码深度分析 - 04 命令系统

## 1. 命令系统架构

### 1.1 命令类型

Claude Code 的命令系统支持三种命令类型，分别适用于不同的交互场景：

- **LocalCommandCall**: 异步命令，接收 `(args, context)` 参数，返回文本结果。适用于执行后立即返回结果的简单操作，如 `clear`、`compact` 等。
- **LocalJSXCommandCall**: JSX 命令，接收 `(onDone, context, args)` 参数，返回 React 组件。适用于需要复杂 UI 交互的命令，如 `model`、`doctor`、`help` 等。通过 `onDone` 回调通知命令执行完毕。
- **PromptCommand**: 提示命令，生成 prompt 内容并注入到对话上下文中。适用于需要向 AI 发送特定指令的场景，如 `init` 命令会生成分析代码库的 prompt。

### 1.2 命令来源（按优先级）

命令系统从多个来源收集可用命令，按以下优先级排列（高优先级覆盖低优先级）：

1. **bundledSkills** -- 打包技能：随 Claude Code 一起分发的内置技能，优先级最高
2. **builtinPluginSkills** -- 内置插件技能：由内置插件提供的技能命令
3. **skillDirCommands** -- 技能目录命令：从用户配置的技能目录（`~/.claude/skills/` 等）加载的命令
4. **workflowCommands** -- 工作流命令：由工作流系统注册的命令
5. **pluginCommands** -- 插件命令：由第三方插件注册的命令
6. **pluginSkills** -- 插件技能：由第三方插件提供的技能命令
7. **COMMANDS()** -- 内置命令（约 80+ 个）：Claude Code 核心代码中定义的命令，作为基础命令集

这种分层设计允许用户和插件扩展命令系统，同时保证核心命令的稳定性。高优先级的命令可以覆盖低优先级的同名命令。

### 1.3 命令注册与发现

命令系统提供了一组 API 用于命令的注册、查找和缓存管理：

- **`getCommands(cwd)`**: 获取指定工作目录下所有可用的命令集合，整合所有来源的命令并按优先级合并
- **`findCommand(name)`**: 按名称查找命令，支持模糊匹配和别名解析
- **`getCommand(name)`**: 精确获取指定名称的命令定义
- **`hasCommand(name)`**: 检查指定名称的命令是否存在
- **`meetsAvailabilityRequirement(command, context)`**: 检查命令在当前上下文中是否可用（如远程模式、IDE 模式等限制）
- **`clearCommandsCache()`**: 清除命令缓存，在插件加载/卸载或技能目录变更时调用

命令查找过程遵循优先级链：先查高优先级来源，找到即返回，确保同名命令的高优先级版本优先被使用。

### 1.4 命令过滤

为了在不同运行模式下保证安全性，命令系统实现了多层过滤机制：

- **`filterCommandsForRemoteMode`**: 远程模式安全命令过滤，仅暴露在远程执行环境中可安全使用的命令子集
- **`isBridgeSafeCommand`**: 桥接安全命令检查，判断命令是否可以通过 IDE 桥接安全执行
- **`REMOTE_SAFE_COMMANDS`**: 远程模式允许的命令白名单集合
- **`BRIDGE_SAFE_COMMANDS`**: 桥接模式允许的命令白名单集合
- **`INTERNAL_ONLY_COMMANDS`**: 仅限内部使用的命令集合，不会暴露给用户

这些过滤机制确保了在受限环境（如远程执行、IDE 集成）中，只有经过安全审查的命令可以被调用，防止潜在的安全风险。

## 2. 核心命令详解

### 2.1 init 命令

- **类型**: Prompt
- **功能**: 分析代码库并创建 `CLAUDE.md` 项目配置文件
- **流程**: 采用两阶段设计
  - **第一阶段（询问）**: 向用户询问项目基本信息，如项目类型、技术栈、构建方式等
  - **第二阶段（探索）**: 基于用户回答，自动探索代码库结构，分析关键文件和目录，最终生成 `CLAUDE.md`

`CLAUDE.md` 文件作为项目的上下文配置，帮助 Claude Code 理解项目结构和约定，是项目级配置的核心。

### 2.2 model 命令

- **类型**: JSX
- **功能**: 模型选择器包装，提供交互式模型切换界面
- **特性**:
  - **Fast Mode**: 快速模式切换，使用轻量级模型加速响应
  - **Effort 级别**: 支持 `low`、`medium`、`high` 等不同推理努力级别
  - **验证**: 模型切换前验证模型可用性和 API 访问权限
  - **模型信息展示**: 显示模型名称、上下文窗口大小、定价等信息

### 2.3 compact 命令

- **类型**: Local
- **功能**: 对话压缩，减少上下文窗口占用
- **模式**:
  - **Reactive Compact**: 响应式压缩，当上下文接近窗口限制时自动触发
  - **Micro Compact**: 微型压缩，仅压缩最旧的消息，保留近期上下文
  - **Session Memory Compact**: 会话记忆压缩，将重要信息提取为摘要形式保留

压缩策略会保留关键信息（如文件路径、重要决策），同时移除冗余内容，确保在有限的上下文窗口内维持有效的对话历史。

### 2.4 doctor 命令

- **类型**: JSX
- **功能**: 诊断屏幕，全面检查 Claude Code 运行环境
- **检查项目**:
  - 版本信息和更新状态
  - API 连接和认证状态
  - 环境变量配置
  - 终端兼容性
  - MCP 服务器状态
  - 插件加载状态
  - 权限配置

### 2.5 help 命令

- **类型**: JSX
- **功能**: 渲染帮助界面，展示所有可用命令和使用说明
- **特性**:
  - 按类别分组展示命令
  - 支持搜索过滤
  - 显示命令别名和快捷键
  - 展示命令简要描述

### 2.6 resume 命令

- **类型**: JSX
- **功能**: 会话恢复，从历史会话中恢复之前的对话
- **特性**:
  - **UUID 搜索**: 通过会话 UUID 精确恢复
  - **标题搜索**: 通过会话标题模糊匹配
  - **跨项目检测**: 自动检测并标记来自不同项目的会话
  - **渐进式加载**: 会话列表按需加载，避免一次性加载过多数据

### 2.7 clear 命令

- **类型**: Local
- **功能**: 清空当前对话历史，重置上下文窗口
- **行为**: 保留系统配置和会话元数据，仅清除消息历史

以下是 Claude Code 所有 80+ 个内置命令，按功能分类：

| 类别 | 命令 |
|------|------|
| **核心** | `init`, `model`, `compact`, `clear`, `doctor`, `help`, `resume`, `exit` |
| **配置** | `config`, `theme`, `color`, `keybindings`, `permissions`, `privacy-settings`, `output-style`, `vim`, `voice` |
| **会话** | `session`, `cost`, `stats`, `usage`, `context`, `memory`, `tasks`, `plan` |

### 命令分类说明

- **核心命令**: Claude Code 的基础功能命令，涵盖初始化、模型管理、对话管理等核心操作
- **配置命令**: 用户偏好和系统配置相关，包括主题、快捷键、权限、输出风格等
- **会话命令**: 对话会话管理，包括成本统计、上下文查看、任务管理等
- **Git 命令**: 与 Git 版本控制集成，支持分支管理、Diff 查看、PR 审查等
- **远程命令**: 远程开发和 IDE 集成相关，支持远程环境配置和桥接
- **MCP 命令**: Model Context Protocol 相关，管理 MCP 服务器和 GitHub App
- **插件命令**: 插件和技能系统管理，包括插件安装、技能查看、钩子配置
- **工具命令**: 实用工具集，包括文件管理、导出、沙箱切换等
- **信息命令**: 信息查询类，包括版本更新、费率限制、反馈等
- **Agent 命令**: AI Agent 相关配置，包括多 Agent 管理、推理努力级别等
- **其他命令**: 杂项功能，包括目录管理、浏览器集成、认证等

## 4. 命令与工具的关系

命令系统和工具系统在 Claude Code 中并非孤立存在，而是通过多层机制相互关联和协作：

### 4.1 SkillTool 调用命令

`SkillTool` 是连接命令系统和工具系统的桥梁。它可以将 `Prompt` 类型的命令包装为工具，使 AI 能够通过工具调用机制间接执行命令。这意味着 AI 可以根据上下文需要，主动调用 `init` 等 Prompt 类型命令。

### 4.2 斜杠命令技能

`getSlashCommandToolSkills` 函数负责获取所有可用的斜杠命令技能，将这些命令转换为工具描述，使 AI 能够感知到可用的命令集合，并在适当的时候建议用户使用。

### 4.3 双向调用关系

```
用户输入 "/command" --> 命令系统 --> 执行命令逻辑
                                          |
                                          v
                                    可能触发工具调用
                                          |
                                          v
AI 决策 --> 工具系统 --> SkillTool --> 调用 Prompt 命令
```

- **命令触发工具**: 某些命令（如 `init`）在执行过程中会调用文件读取、目录扫描等工具
- **工具调用命令**: AI 通过 `SkillTool` 可以调用 Prompt 类型的命令，实现命令的自动化执行
- **命令注册工具**: 插件和工作流系统可以通过命令注册机制添加新的工具能力

这种双向关系使得命令系统和工具系统形成了一个有机的整体，既支持用户的直接操作，也支持 AI 的自动化决策。
